# デスクトップ版（Tauri）の作り

v0.2.0 から、ブラウザで開く代わりに**専用の窓（倉入実績集計.exe）**で動かせます。**ポートを使いません。**
ブラウザ版（`Start.vbs`・`start.bat`）もそのまま残してあり、予備として使えます。作りは python-web-tools のデスクトップ版と同じです。

## 何が何をするか（各言語が得意なことをする）

```
倉入実績集計.exe（Rust / Tauri）                 … src-tauri/
 ├─ 窓（WebView2）・二重起動の防止・終了の確認（データ更新の実行中なら訊く）
 ├─ フォルダ・ファイルを選ぶ窓（Windows 標準。「パスの設定」の「選ぶ…」）
 ├─ Python を子として起動・見張り（見つからない・落ちたら理由の画面）
 ├─ Windows のジョブ: exe が終わると Python・SymNavi・cscript・Excel もまとめて止める
 ├─ 起動の記録 logs\actualsdashboard\actualsdashboard_起動_<PC>_<日付>.log
 └─ 画面の要求（app://…）を受けて Python の標準入力へ渡す
        │ 標準入出力（1 件 = 見出し 1 行 + 本文）
        ▼
bridge.py（Python 標準ライブラリだけ）            … ポートを使わない入口
 └─ ブラウザ版と同じ handler（actuals/web/server.py）に 1 件ずつ通す（待ち受けない）
        ▼
actuals/（Python）… 判定・計算・集計・取り込み・SymNavi・ログ（ブラウザ版と同じもの）
actuals/web/static/（JS）… 画面（デスクトップ版のときだけ「選ぶ…」を外枠に頼む）
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・二重起動・Python の見張り・選ぶ窓・子の後片付け | OS の窓とプロセスを扱うのが得意。exe 1 つで配れる。強制終了でも SymNavi・Excel を残さない |
| **Python**: 判定・集計・取り込み・SymNavi | 重い処理は無い（987 件の取り込み 0.08 秒・月の集計 0.17 秒・年の集計 0.17 秒）。旧 VBA と同じ結果を守る試験がこの形で書かれている。書き直す利点が無く、危険だけがある |
| **JS**: 画面 | 今までどおり |

## ポートを使わない仕組み

- 画面は独自の宛先 `app://localhost/`（Windows の WebView2 では `http://app.localhost/`）を読む。ネットワークを通らない
- 外枠はその要求を Python の標準入力へ渡し、標準出力から応答を受け取る（`src-tauri/src/bridge.rs` と `bridge.py`）
- Python 側は、要求を HTTP の形にして**ブラウザ版と同じ handler** に読ませる（`server.call_handler`）。
  画面・トークン・Host の確認（デスクトップ版は `app.localhost` だけ）・エラーの形はブラウザ版と同じ道を通る
- 試験: `tests/test_bridge.py`（ソケットを開くと落ちるようにして動かす）、`scripts/desktop_smoke.py`（exe を本当に起動して、どのプロセスも待ち受けていないことを見る）

## ブラウザ版とデスクトップ版は同時に動かない

| 先に動いている | 後から開いた | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 窓に「ブラウザ版が動いています。同時に使えません」と出して止まる（ブラウザ版はそのまま） |
| デスクトップ版 | ブラウザ版 | 「デスクトップ版が動いています」と出して止まる（終了コード 5。デスクトップ版はそのまま） |
| デスクトップ版 | デスクトップ版 | 新しく起動せず、開いている窓を前に出す |
| ブラウザ版 | ブラウザ版 | 開いている画面をもう一度開く（前と同じ） |

両方とも同じ `web.lock`（データの場所の runtime）を取り合い、中に「どちらの版か・番号・起動時刻」を書く。
番号と起動時刻の両方が合う時だけ「動いている」とみなす（PC の再起動で番号が使い回されても止まらない）。
後から開いた方は、先に動いている方を止めたり終わらせたりしない。

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 業務画面 |
| 窓の × / 画面の「終了」 | データ更新の実行中なら「中断して終了しますか？」と訊く |
| 放置 | 自動では終わらない（窓を閉じたら終わる。ブラウザ版の 12 時間の自動終了は無し） |
| stop.bat | 窓に「閉じて」と頼む（× と同じ確認）。15 秒で終わらなければ exe ごと止める（Python・SymNavi・Excel も止まる） |
| Python が見つからない・起動できない | 理由と次にすること・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |

Python は**同梱しません**。各 PC の Python を使います（`config\python_path.txt` → `python.exe` → `py.exe -3` の順。
`ACTUALS_PYTHON` で指定もできる）。追加のパッケージは要りません。各 PC に要るのは WebView2（Windows 10/11 には普通入っています）です。

## 作り方

**Windows 版は GitHub Actions が作ります**（`.github/workflows/desktop-windows.yml`）。押すたびに Python の試験・Rust の試験・
exe の作成・exe を起動しての確認まで流れ、成果物 `ActualsDashboard-windows` に `倉入実績集計.exe` が入ります。
配るときは、ツールのフォルダ（`start_app.py`・`bridge.py` のある所）の**直下**に置きます。

手元で作るとき（開発機）:

```
cd src-tauri
cargo test --release
cargo build --release            # target/release/ActualsDashboard(.exe)
python ../scripts/desktop_smoke.py --exe target/release/ActualsDashboard    # Linux は xvfb-run を前に付ける
```

版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の 3 か所。食い違うと試験が落ちる。

## 確かめきれていないこと（Windows の実機で見る）

この版の確認は Linux（WebKitGTK）の上で窓を実際に動かして行いました。Windows では GitHub Actions が
「起動して画面が届く・待ち受けない・2 回目とブラウザ版が止まる・stop.bat で止まる・止めたら Python も終わる」まで確かめます。
次は**実機で人が見る**必要があります:

- 「データ更新」で SymNavi が動き、窓を閉じた時に SymNavi・Excel が残らないこと
- 「選ぶ…」で Windows のフォルダ・ファイルを選ぶ窓が出ること（共有フォルダ \\サーバー\共有 も選べること）
- 月の集計の「印刷」から紙が出ること（WebView2 の印刷）
- 「開く」でエクスプローラーが開くこと
