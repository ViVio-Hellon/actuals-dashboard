## 機能移植（2026-10-30）

指摘: 「RNEConverter のフォルダ：要設定」になる。RNEConverter に頼む方式ではなく機能移植ではだめか。RNE が設定できないので動作確認できない。

原因: 要設定の判定は「RNEConverter が新しい版（`--rne` 指定に対応）か」「SymNavi のログインが RNEConverter に登録済みか」も見ていたため、
フォルダが正しくても、手元の RNEConverter が追加前の版、または登録の場所（`%USERPROFILE%\RNEConverter\config\credentials.json`）に無いと要設定になった。

対応: RNEConverter に頼むのをやめ、SymNavi からの取り出しをこのツールに移植した。

| 項目 | 内容 |
|---|---|
| 写したもの | RNEConverter（8e41e3f）の `app/extract/`（SymNavi・DDE・拡張 API・クリップボード・画面監視・VBS・navi_api.ps1）、`app/transform/`（xls・TSV 読取）、ロック。中身は変えず `actuals/symnavi/` に置いた（直す時は RNEConverter と揃える） |
| 取り出し方 | RNEConverter と同じ（拡張 API → 画面で xls 保存 → Excel 経由）。結果は中間の SQLite を作らずに蓄積へ取り込む |
| パスの設定 | ①-1 RNE ファイル ①-2 SymNavi.exe ①-3 サーバー名 ①-4 ログイン ／ ② 共有フォルダ ／ ③ CSV・ログ ／ 詳細（作業フォルダ・待ち時間・cscript）。RNEConverter のフォルダ・出力先・ファイル名の項目は無くした |
| ID・パスワード | この PC の `<データの場所>\config\credentials.json`（RNEConverter と同じ形）。画面・ログ・共有には出さない。未登録なら同じ PC の RNEConverter の登録 → 環境変数を使う |
| RNEConverter 側 | 先に足した `--rne` などと KURAIRE の行は不要（このツールからは呼ばない） |
