# 倉入実績集計（actuals-dashboard）

旧 Excel VBA ブック「倉入実績グループ集計」（SymNavi の倉入実績を 15 グループに振り分け、日別・月別・直別に
重量と枚数を集計する）を、ブラウザで使う業務ツールに置き換えたものです。

- **Python 標準ライブラリだけ**で動きます（http.server / sqlite3 / csv / logging / subprocess）。追加パッケージ不要。
- **SymNavi からの取り出しもこのツールの中で行います。** 「データ更新」で SymNavi を起動し、RNE を実行して当月の倉入実績を取り出し、
  そのまま共有の蓄積に取り込みます（SymNavi とのやり取りは RNEConverter のものを `actuals/symnavi/` に写して使用。RNEConverter は不要）。
- 見た目・部品・決まりは **python-web-tools**（梱包資材総合ツール）と同じです（tokens.css / components.css / toast / askbox、
  エラー応答の形、ログの決まり、`config/app.json`）。
- 判定・計算・集計は旧 VBA と同じ結果になることを、受領ブックの保存値（987 件）と全件照合しています。

解析と移植の記録: `docs/01_現行VBA解析.md`、`docs/02_移植計画.md`

```
Python（標準ライブラリだけ）
  ├─ http.server ── ブラウザ画面（127.0.0.1、起動ごとのトークン）
  ├─ sqlite3 ────── 共有フォルダ: 条件表・手動訂正（actuals_master.sqlite3）／蓄積した実績（actuals_history.sqlite3）
  ├─ csv ────────── 月集計・明細・年集計を指定フォルダへ書き出し（ダウンロードはしない）
  ├─ logging ────── <ログの出力パス>\actualsdashboard\actualsdashboard_<PC>_<日付>.log ／ _記録_<PC>_<日付>.jsonl
  ├─ subprocess ─── 「データ更新」: SymNavi.exe を起動（拡張 API は PowerShell の navi_api.ps1）
  ├─ ctypes ─────── SymNavi への DDE（Open → Save → Close。旧 VBA と同じ手順）
  └─ cscript ────── 上の 2 つがだめな時だけ、旧 VBA と同じく Excel 経由で取り出す（予備）
（Access は使わないので ADODB・ACE は使わない）
```

## 画面

| 画面 | 中身（旧ブックとの対応） |
|---|---|
| 1 月の集計 | グループ（月計・件数）／日別グラフ（合計・直別。重量は棒、枚数は線）／グループ × 日の表／明細（旧 月集計 + ｸﾞﾗﾌ）。グループを押すとグラフと明細が切り替わる（旧「レ」）。表のセルを押すとロットの一覧、ロットを押すと判定の経過 |
| 2 年の集計 | 年度（4/1〜3/31）の月別グラフ（グループ別に色分けして積む）と、月別・日別の表（旧 年集計）。見出しは条件表のグループ名で、グラフと同じ色の見本付き。棒を押すとその月の「月の集計」へ |
| 3 振り分け確認 | 未分類のロット（外れた理由つき）と手動訂正の一覧。訂正はここか、ロットの引き出しから（旧 修正シート A 列） |
| 4 条件表 | 15 グループの条件（旧 設定シート 5〜19 行）、寸法の基準（製造/ｵｰﾀﾞｰ）、判定方式。保存前に「影響を確認」 |
| 5 データ | データ更新（進み具合・中断）、取り込みの記録、月ごとの件数、手作業の取り込み（xls・貼付け）、旧ブックからの移行 |
| 6 パスの設定 | RNE ファイル、SymNavi.exe・サーバー名・ログイン、共有フォルダ、書き出し先、ログ |

グラフの見た目は all-tools（日報複合ツール）と同じ決まりです。
直の色は Excel のグラフと同じ 1 直 青・2 直 赤・3 直 緑で、明細の「直」の札も同じ色です。
「合計」は棒を直ごとに下から積み、日の合計どおりの高さにします。積んでも合計と合わない時と太陽暦は 1 色の棒です。
枚数の線は直のどの色とも違う紫で、地の色の縁取りを付けて棒の上でも消えないようにしています。
凡例は形でも分けています（棒は四角、線は横棒）。日曜は表と同じ淡い地で、横軸は 1〜末日をすべて出します。
「直別」の 3 枚は同じ目盛りで、直どうしを高さで比べられます。棒や日の上を指すと、その日の重量（直ごと）と枚数が出ます。

年の集計のグラフは、月ごとの棒をグループ別に積みます（下からグループ番号の順）。色は all-tools の 10 色
（P型/D型色覚でも見分けられる組）で、年度の重量が多い 9 グループに番号の順で 1〜9 色目を付け、残りは淡い灰の「その他」にまとめます。
重量・枚数どちらを見ても同じ色で、表の見出しにも同じ色の見本が付きます。

暦（現場暦 / 太陽暦）は各画面の切替で選びます。現場暦は BOX実績_作業終了_日付で集計して直（7〜15 時 1 直、15〜23 時 2 直、他 3 直）を出し、
太陽暦は最小の倉入完了_年月日で集計して直は出しません（旧ツールと同じ）。

## 準備

1. Python 3.8 以上（追加パッケージ不要）。
2. SymNavi（`C:\NAVICL\bin\SymNavi.exe`）が入っている PC で使う。RNEConverter は要らない。
3. `Start.vbs` で起動し、「パスの設定」で次を指定する（下の節）。最低限は ①-1 RNE ファイル・①-4 SymNavi のログイン・② 共有フォルダ。
4. 旧ブックがあれば、データ画面の「旧ブックからの移行」で DATA と手動訂正を取り込む
   （`start.bat --import-workbook 旧ブック.xlsm` でも可）。

## パスの設定（画面 6）

データの流れの順に並んでいます。

```
①-1 RNE ファイル ──SymNavi（①-2 本体・①-3 サーバー・①-4 ログイン）──▶ 当月の倉入実績 ──取り込み──▶ ② 共有フォルダ ──▶ 集計画面・③-1 CSV
```

| 番号 | 項目 | 何に使うか |
|---|---|---|
| ①-1 | RNE ファイル | SymNavi に渡す問い合わせ。旧ブックと同じフォルダにあった `梱包実績(当月_倉入れ日付順).RNE` を選ぶ |
| ①-2 | SymNavi.exe | SymNavi 本体。既定は旧ツールと同じ `C:\NAVICL\bin\SymNavi.exe` |
| ①-3 | SymNavi のサーバー名 | 既定は旧ツールと同じ `NlmFaNgyNavd` |
| ①-4 | SymNavi のログイン | ID とパスワード（旧ブックではフォームに直接書かれていたもの）。この PC の `<データの場所>\config\credentials.json` にだけ保存し、画面・ログ・共有フォルダには出さない。未登録でも、同じ PC の RNEConverter に登録済みならそれを使う |
| ② | 共有フォルダ | 取り込んだ倉入実績（月ごとに蓄積）・グループの条件表・手動訂正。全 PC で同じ場所にすると、どの PC で「データ更新」しても全員が同じ集計を見る。空欄はこの PC の中だけ（試用） |
| ③-1 | CSV の書き出し先 | 「CSV に」ボタンで書くフォルダ |
| ③-2 | ログの出力パス | ログを書く場所（フルパス。例 `\\サーバー\共有\logs`）。この下に `actualsdashboard\` を作って書く（下の「ログ」）。共有フォルダにすると全 PC の分を 1 か所で見られる。**空欄はこの PC の logs**。保存するとすぐ切り替わる（再起動不要）。右の「状態」に実際に書くフォルダとファイル名、「開く」でそのフォルダ |
| 詳細 | 作業フォルダ・待ち時間・cscript.exe | SymNavi の結果を一時的に置く場所（既定 `{DATA}\work`）、SymNavi の起動待ち（20 秒）・結果待ち（120 秒）、予備の Excel 経由で使う cscript.exe |

- 「選ぶ…」でフォルダを辿って選べます（`\\サーバー\共有` を直接入力もできます）。「開く」はエクスプローラーで開きます。
- 入力を変えると、保存する前に右の「状態」が変わります（ある・書ける・既定と違う）。
- 「データ更新」の取り出し方は RNEConverter と同じです: 拡張 API で取り出し → だめなら画面（DDE）で xls に保存させて読む →
  さらにだめなら旧 VBA と同じ Excel 経由。進み具合はデータ画面に出て、「中断」で SymNavi ごと止められます。
- 既定値はツールのフォルダの `config\settings.json`。全 PC に同じ既定を配る時はここを書き換えて配ります。画面で変えた項目だけが PC ごとに残ります。

## 起動と終了

| ファイル | 動き |
|---|---|
| `Start.vbs` | 通常の起動（コンソールなし）。すでに起動していれば、その画面を開く |
| `start.bat` | 同じ画面を開き、ログをコンソールにも出す。`start.bat --import-workbook 旧ブック.xlsm` で移行 |
| `stop.bat` | 画面に終了を頼む（画面右上の「終了」と同じ）。応答しない・15 秒たっても終わらない時は、記録してあるプロセスを強制終了（taskkill /T /F）し、残ったロックを片付ける |

画面をすべて閉じると 2 分後、開いたまま問い合わせが無ければ 12 時間後に自動で終わります。
どの .bat も `config\python_path.txt` に Python のフルパスを書くとそれを使います（pythonw.exe を書いても .bat はコンソールの出る python.exe を使う）。

## データの持ち方

| もの | 置き場所 | 書き方 |
|---|---|---|
| 倉入実績（取り出したもの） | 作業フォルダに一時的に置き、取り込んだら消す | SymNavi の結果を読んで、そのまま蓄積へ |
| 蓄積した実績 | 共有 `actuals_history.sqlite3` | ロット番号ごとに蓄積。同じロットは新しい内容に置き換え、消しはしない |
| 条件表・手動訂正・変更履歴 | 共有 `actuals_master.sqlite3` | 全 PC 共通。版番号・画面が見ていた値と比べ、別の人の保存を上書きしない（409） |
| 設定・ログ・写し・SymNavi のログイン | `%USERPROFILE%\ActualsDashboard`（`ACTUALS_DASHBOARD_HOME` で変更可） | PC ごと |

**共有フォルダを後から決めた時:** それまで ② が空欄で、この PC の中（`%USERPROFILE%\ActualsDashboard\shared`）に貯めた分は、
「データ」画面の「この PC に貯めた分を共有フォルダへ移す」で移せます（② を保存した時にも知らせます）。
共有にある物は上書きしません（同じロットの実績・同じロットの手動訂正は共有のまま。条件表は共有がまだ初期値の時だけ写す）。
移した後、この PC の物は `…_移した_<日時>.sqlite3` の名前で残します（消さない）。取り込みの記録には「この PC から移した」と残ります。

共有の SQLite には複数の PC が直接書きません（SMB 上ではロックが正しく効かないことがあるため）。
保存のたびに「ロックファイルで 1 台ずつ → 手元で直す → 一時ファイルを置いて os.replace で差し替え」、
読む時は「変わっていれば手元に写して読み取り専用で読む」です。共有に届かない時は手元の最後の控えを表示し、帯で知らせます。
その日最初の保存の前に `backup\` へ控えを残します（14 日分）。

## 判定方式（2026-10 の業務確認による修正）

旧 VBA の NOT 条件には 2 つの誤りがあり、修正版を既定にしています。条件表の画面で旧 VBA と同じ方式に戻せます。

| | 旧 VBA | 修正版（既定） |
|---|---|---|
| NOT 条件の材質 | 調質の数値（Val）と比べていた（列ずれ） | 材質と比べる |
| NOT 条件に当たった時 | 判定をやめる（それまでに当たりが無いロットは未分類） | その行だけ外して次の行へ |

受領ブック（2022/06）では、旧 VBA で未分類だった 17 件（45,895.8 kg）が ﾄｯﾄ・SVC・LVC に入ります（他のロットは変わりません）。
同時VC（表VC・裏VC の列）は、現在の RNE に列が無いため旧ツールと同じく成立しません（別のフラグを調査中のため保留）。

## ログ

all-tools（日報複合ツール）と同じ決まりです。

```
<ログの出力パス>\
└─ actualsdashboard\                                   ツール ID（半角英小文字）のフォルダ。出力パスの直下には置かない
   ├─ actualsdashboard_<PC>_<YYYYMMDD>.log            動いた記録（人が読む。全部）
   └─ actualsdashboard_記録_<PC>_<YYYYMMDD>.jsonl     出来事（1 行 1 件の JSON）
```

- 名前に PC 名が入るので、共有フォルダを指しても何台もが同じファイルに書きません。
- ログの出力パスは「パスの設定」③-2 で指定します。全 PC に同じ出力パスを配る時は、ツールのフォルダの
  `config\settings.json` の `"log_dir"` に書いて配ります（画面で変えた PC はその値が優先）。
- 出力パスが空欄・届かない時は、この PC の `%USERPROFILE%\ActualsDashboard\logs\actualsdashboard\` に同じ形で書きます
  （ログが書けないことで止めない。書くのは裏のスレッドで、5 分ごとに出力パスを試し直す）。設定画面の「いまの状態」に書き先と理由が出ます。
- 前の形（v0.1.0: `<出力パス>\actuals-dashboard\actuals-dashboard_<PC>_<日付>.log`）は移さない・もう書かない。
  古いものを片付ける時だけ同じに扱います。
- 古いログの片付け（既定 90 日、`log_keep_days`）は、このツールの・この PC のファイルだけ。ほかの PC・ほかのツール（`nippou\` など）には触りません。
- SymNavi のパスワードは、どの記録にも出しません（出てきたら `****`）。

| 出来事（kind） | 中身 | いつ |
|---|---|---|
| 起動・終了 | ツール名・版・モード・PC・利用者・pid・Python／終了の理由・終了コード・稼働秒 | 起動時・終了時（画面の終了、画面を閉じた、放置、stop.bat） |
| 処理開始・処理終了 | 処理名・開始時刻・秒・結果（正常／中断／エラー）・件数など | 押した操作（データ更新・取り込み・保存・CSV など）は必ず組で。画面の読み込みは 3 秒以上・失敗の時だけ |
| 読込 | 読込先・件数・秒 | SymNavi の結果、集計に使うロット、共有のファイルの写し、xls・貼付け・.sqlite3・旧ブック |
| 保存 | 保存先・件数・秒 | 蓄積・条件表・手動訂正（共有）、その日の控え、CSV、設定、SymNavi のログイン（中身は書かない） |
| 警告 | 内容・発生箇所（続けたか、中断したか） | すべての WARNING（入力の誤り・別の PC が保存中などの「中断」も） |
| エラー | 日時・ツール名と版・PC・利用者・実行していた処理（入れ子）・種類・メッセージ・スタックトレース・使っていたファイルや DB・直前の処理（最近 15 行）・エラー番号 | 予期しないエラー。画面に出るエラー番号（`E yymmdd-HHMMSS-xx`）で探せる |
| 操作 | 画面で押した操作と主な値 | データ更新・中断・取り込み・手動訂正・条件表・CSV・設定・ログイン登録（ID のみ）・終了 |
| 長引き | まだ終わらない処理・経過秒 | 30 秒・10 分を超えた時、その後 10 分ごと（固まったまま強制終了されても、どこで止まったか分かる） |

処理時間: 3 秒未満 INFO、3 秒以上・10 秒以上・30 秒以上は WARNING（`[3秒以上]` などを付ける）、エラーは ERROR。
各行の `[6 桁]` は操作番号で、1 回の操作の行をまとめて追えます。
